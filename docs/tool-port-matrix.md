| --- | --- | --- | --- |

Additional notes:
- silver has no separate list_files concept upstream; Hermes folds it into search_files(target=files). This is the main naming mismatch.
- Names that already match 1:1 in spelling: read_file, write_file, memory, session_search. Names that must change: search_text -> search_files, list_files -> search_files (or alias), apply_patch -> patch, run_command -> terminal (with a schema decision).
- Schema property renames inside matching tools: memory (file->target, operation->action, old->old_text, new->new_text) and session_search (add fields).
- read_file/write_file/patch/search_files are already workspace-confined via Workspace::resolve_path and require_workspace(); that invariant matches Hermes' confinement expectations and should be retained.

## 4. Implementation checklist

> Historical: this was the work plan. Every PORT-1:1 and PORT-MINIMAL workstream below has shipped
> except `clarify`; see [Implementation status](#implementation-status) for the live tree.

Grouped PORT-1:1 and PORT-MINIMAL tools, with the shared backend each workstream needs. "Existing" means code already in crates/silver-core/src/tools/.

### A. Filesystem (PORT-1:1) - read_file, write_file, patch, search_files
- Shared backend: workspace path confinement + canonical root (Workspace::resolve_path, guard/mod.rs), atomic write (write_atomic), UTF-8-safe byte capping, a ripgrep-equivalent search engine (shell out to rg or use the grep/ignore crates), and a per-run read/write record for the write-before-read guard.
- Existing to extend: tools/fs.rs (read_file, list_files, search_text), tools/write.rs (write_file, apply_patch), tools/patch.rs (apply_unified_diff).
- Work: rename search_text/list_files -> search_files; rename apply_patch -> patch and add the find/replace schema + fuzzy matching; upgrade read_file output/pagination; add the read-before-write guard and syntax checks to write_file.

### B. Terminal + process (PORT-1:1 terminal only) - terminal
- Shared backend: the filtered child-environment builder (PRESERVED_ENV allow-list), the Tokio subprocess runner with timeout, CancellationToken and process-group kill, and approval gating (RiskLevel::Process).
- Existing to extend: tools/command.rs (RunCommandTool), crate::tool::ApprovalPolicy.
- Work: expose the Hermes terminal name/schema (command/timeout/workdir) or add it alongside run_command; keep the argv contract for run_command. process_manage (background registry) is YAGNI-DEFER, so background/notify/pty are not part of this workstream yet.

### C. Web (PORT-MINIMAL) - web_search, web_extract
- Shared backend: one HTTP client (for example reqwest) shared by both tools, an HTML-to-markdown/readability extractor, local PDF text extraction, and a single pluggable search-provider trait with one local/free first backend (DuckDuckGo HTML or an operator-configured SearXNG URL). No SaaS keys required.
- New code: tools/web/ (new module); no existing file to extend.

### D. Skills (PORT-1:1 + PORT-MINIMAL) - skills_list, skill_view, skill_manage
- Shared backend: a skills root directory (workspace or profile home), a SKILL.md YAML frontmatter parser, linked-file enumeration (references/templates/scripts), and safe atomic writes.
- New code: tools/skills.rs (new). No hub, marketplace, curator, provenance/ledger or scanner.

### E. Todos + clarify (PORT-1:1) - todo_list, clarify
- Shared backend: per-session state persisted in SQLite plus the SSE event emitter with a client-response round-trip. clarify reuses the approval wait (approval.required -> POST response); todo_list reuses the session store.
- Existing to extend: event.rs (EventEmitter), session.rs, and the approval flow.

### F. Code execution (PORT-MINIMAL) - execute_code
- Shared backend: a local Python interpreter + persistent kernel process, a JSON-RPC tool bridge that exposes the ToolRegistry functions to generated Python bindings, and the same filtered environment as terminal. No remote kernels and no Vercel sandbox.
- New code: tools/code_execution.rs + a Python bridge script. No existing file to extend.

### G. Recall (already present; upgrade to 1:1) - session_search
- Shared backend: the SQLite FTS session store (session_search.rs / SessionSearch). The Markdown memory store (memory.rs / MemoryStore) that once backed `memory` was retired in favour of the managed ai-memory server.
- Existing to extend: tools/session_search.rs (add the discovery/scroll/read/browse shapes and filters; drop profile).

### Deferred (not in any MVP workstream)
- Browser stack (browser_navigate/snapshot/click/type/scroll/back/press/get_images/vision/console/cdp/dialog, all browser_vault_*, browser_exec): needs a browser engine + agent-browser/CDP or cloud provider; vault needs OS keychain + password managers.
- Multimodal beyond a single picture: video_analyze, image_generate and text_to_speech need
  image/video/audio providers and delivery. `vision_analyze` shipped as `view_image`.
- Orchestration (all kanban_*): multi-agent orchestration is out of scope.
- Automation/integrations (cronjob_manage, all ha_*, computer_use, manage_connections, MCP and plugin toolsets): missing scheduler, Home Assistant, cua-driver, connector gateway/MCP client, plugin ABI. process_manage was on this list; the terminal backend later supplied the per-scope process table and it shipped (see Implementation status).
- Platform adapters (all hermes-* bundles, discord/discord_admin, yuanbao, feishu_doc/feishu_drive, spotify, desktop_ui/project/bot_room/context_engine): post-MVP clients/surfaces.
